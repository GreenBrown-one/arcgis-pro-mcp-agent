# Phase 2 实机兼容性修复设计规格

- 日期：2026-07-30
- 状态：方案 A 已获用户同意，待书面规格确认
- 适用范围：ArcGIS Pro Agent Phase 2 本机开发版
- 目标环境：Windows、ArcGIS Pro 3.7、ChatGPT 订阅账号、Codex App Server

## 1. 背景与实机证据

Phase 2 的非图形实现、测试和安装链路已经完成，但首次实机联调暴露出三项兼容性问题：

1. 桌面端仍监听旧版 Codex App Server 通知 `mcpServer/status/updated`；当前协议发送 `mcpServer/startupStatus/updated`。
2. 开发安装后的桌面程序默认启动裸命令 `ArcGISProAgent.Mcp.exe`，而实际 MCP 可执行文件位于同一版本目录下的 `mcp` 子目录中，并不在全局 `PATH`。
3. 窗口在 150% Windows 缩放下只有约 `853 × 533` CSS 像素；页面根节点固定 `min-height: 720px`，导致输入区和右侧上下文入口被裁切。

已确认 MCP Server 与 ArcGIS Pro Add-In 的直接 R0 JSON-RPC 通路可用，因此本次只修复桌面运行时兼容层和布局，不扩展 GIS 能力。

## 2. 目标

本次修复完成后：

1. 创建会话即可触发 ArcGIS MCP 启动和状态发现，不需要先发送一次模型消息。
2. 当前和旧版 MCP 状态通知都能被安全识别，但内部只维护一套状态机。
3. 安装版桌面程序无需修改全局 `PATH` 即可找到同版本的 MCP Server。
4. 在 150% 缩放和约 `853 × 533` CSS 视口下，消息输入区始终可见，ArcGIS 上下文抽屉可打开和关闭。
5. 继续遵守现有线程租约、运行时世代、失败关闭、脱敏和只读实机验证约束。

## 3. 非目标

- 不新增或修改 R0/R1 GIS 工具语义。
- 不实现 R2/R3 写入、保存、编辑或删除操作。
- 不接入 API Key，不读取或记录 ChatGPT 凭据。
- 不写入全局 MCP 配置，不修改系统或用户 `PATH`。
- 不把原始 Codex/MCP 错误文本转发到前端或日志。
- 不在本次改变 Add-In、MCP Server 或桥接协议的业务能力边界。
- 不为旧版和新版协议维护两套并行状态逻辑。

## 4. 决策：旧版状态事件保留为兼容别名

### 4.1 外部协议入口

- `mcpServer/startupStatus/updated` 是当前协议的权威事件。
- `mcpServer/status/updated` 暂时保留为旧版兼容别名。
- 两个事件名都只进入同一个解析器和同一个状态转换函数；不会向前端产生两套事件，也不会重复改变状态。
- 重复通知必须幂等：当归一化后的状态未变化时，不产生新的桌面快照。

这里的“合并”仅指内部处理链合并，不修改 Codex 的外部协议，也不把两个事件结构拼接成第三种协议。

### 4.2 允许解析的字段

状态通知只读取：

- `name`
- `status`
- 可选 `threadId`
- 当前事件的可选 `failureReason`，仅映射为本地安全分类

仅接受 `name == "arcgis"`。生命周期只接受 `starting`、`ready`、`failed`、`cancelled`；未知值按未就绪处理。原始 `error` 字段不保存、不记录、不显示。

内部安全失败分类最多包括：

- `startup_failed`
- `reauthentication_required`
- `cancelled`
- `unknown`

旧版事件没有更丰富的失败信息时，只能提供通用分类；它不得覆盖同一运行时世代中已经由当前事件得到的更具体分类。

### 4.3 单一就绪状态机

状态机分别记录当前运行时世代和活动线程的：

- MCP 生命周期状态；
- ArcGIS 工具清单是否通过基线校验；
- 安全失败分类；
- 最后一次有效状态来源。

ArcGIS 只有在以下条件同时满足时才可标记为就绪：

1. 通知中的生命周期为 `ready`；
2. 当前运行时世代的 `mcpServerStatus/list` 响应包含名为 `arcgis` 的服务器；
3. 其工具清单至少包含 Phase 2 健康检查和上下文读取所需的基线工具；
4. 事件属于当前活动线程，或是当前运行时世代允许的全局通知；
5. 现有线程租约和世代校验均通过。

`starting`、`failed`、`cancelled`、清单缺失、超时、协议错误、线程不匹配或世代不匹配都会保持或恢复为未就绪。先到达的 `ready` 通知可以暂存生命周期状态，但必须等工具清单验证完成后才对外就绪；清单先到达时同理。

### 4.4 主动状态发现

成功完成 `thread/start` 并提交活动线程后，桌面运行时发送：

```text
mcpServerStatus/list
{ threadId: <当前线程>, detail: "toolsAndAuthOnly" }
```

该请求用于触发并发现 MCP Server，不依赖首次 LLM turn。请求必须有界等待；失败只会使 ArcGIS 保持未就绪，不应撤销已经成功创建的对话。

通知循环在请求发出前已经运行，因此无论通知先于响应还是响应先于通知，最终都由同一状态机汇合。状态列表响应不含原始启动错误，前端只获得现有的安全连接快照。

### 4.5 旧版兼容入口的生命周期

本阶段不删除旧事件入口，以避免较旧 Codex App Server 立即失效。将来只有在项目明确提高最低 Codex 协议版本、迁移说明完成且兼容测试同步删除后，才可移除该入口。

## 5. 安装版 MCP 可执行文件解析

MCP 命令按以下固定优先级解析：

1. 非空 `ARCGIS_AGENT_MCP_COMMAND`：原样作为最高优先级显式覆盖。
2. 安装布局候选：若当前桌面程序位于 `<版本>/desktop/`，解析并检查 `<版本>/mcp/ArcGISProAgent.Mcp.exe`；存在时使用规范化绝对路径。
3. 开发回退：候选不存在时继续使用裸命令 `ArcGISProAgent.Mcp.exe`，保留源码运行、测试替身和显式 `PATH` 场景。

`ARCGIS_AGENT_MCP_ARGS` 的现有行为保持不变。解析器应以可注入的当前程序路径和文件存在性检查编写，使测试无需依赖真实用户目录。路径可以包含空格，不通过 shell 拼接或重新解析。

这项修复不硬编码盘符、用户名、仓库路径或 ArcGIS Pro 安装目录，也不修改全局环境变量。

## 6. 高 DPI 与受限高度布局

### 6.1 CSS 约束

- `html`、`body`、`#root` 保持 `height: 100%`，移除固定 `min-height: 720px`，并使用 `min-height: 0`。
- `.app-shell` 和中心会话网格允许子项收缩，继续限制整窗溢出。
- `.conversation-body` 负责受限高度下的纵向滚动；头部和 `.composer-wrap` 保持在网格的固定行中。
- 消息列表继续独立滚动，但不得通过自身最小内容高度把输入区推出视口。
- 有效 CSS 宽度小于 `980px` 时，沿用现有右侧上下文抽屉；抽屉按钮、遮罩和关闭按钮必须可通过鼠标和键盘访问。

### 6.2 窗口配置

本次采用 CSS 优先的最小修复。`tauri.conf.json` 的默认物理窗口尺寸和最小尺寸暂不改变；只有自动测试或 150% 实机复验仍证明窗口不可用时，才在同一任务中做有依据的最小调整。

## 7. 安全与故障行为

- 所有新解析均采用字段白名单和枚举白名单，未知结构失败关闭。
- 当前事件和旧版事件的重复、乱序或延迟到达不得绕过线程/世代租约。
- `mcpServerStatus/list` 的未知服务器、未知工具和额外字段不直接暴露给前端。
- 状态发现失败不启动健康轮询工具调用；只有就绪状态机通过后，现有健康轮询才可运行。
- 运行时停止、线程替换、账户退出或窗口关闭沿用现有撤销逻辑，清除本世代的生命周期和清单证明。
- 测试和实机复验不修改或保存任何真实 GIS 项目、图层或数据。

## 8. 测试策略

实现遵循测试驱动开发，先写失败测试，再做最小实现。

### 8.1 Rust

至少覆盖：

- 当前事件名可进入归一化状态机；
- 旧事件名作为别名进入同一状态机；
- 重复事件幂等，不产生重复状态转换；
- 旧事件不能覆盖当前事件的具体失败分类；
- 非 `arcgis`、未知状态、错误线程和过期世代均被拒绝；
- `ready` 与工具清单响应以两种到达顺序汇合；
- `thread/start` 成功后发送带 `threadId` 和 `toolsAndAuthOnly` 的 `mcpServerStatus/list`；
- 状态列表失败或超时保持失败关闭，但对话仍可存在；
- 显式环境覆盖、安装版同级绝对路径、候选缺失开发回退的优先级；
- 带空格的可执行文件路径不经过 shell 拼接。

### 8.2 前端与 CSS

至少覆盖：

- 根节点不再声明固定 `720px` 最小高度；
- 会话主体具备受限高度滚动规则；
- `980px` 以下上下文抽屉媒体规则仍存在；
- 现有前端组件测试、TypeScript 构建和 Tauri 构建继续通过。

若当前测试栈没有浏览器布局引擎，可以用源码规则断言防止回归，但最终必须由实机复验补足视觉证据。

### 8.3 回归与实机复验

完成实现后运行相关 Rust、前端、Tauri、.NET 和安装器验证，并事务性重新安装开发版。实机验收包括：

1. ArcGIS Pro 已启动且 Add-In 已发现；
2. 桌面程序沿用 ChatGPT 订阅登录，不要求 API Key；
3. 新建对话后、发送任何模型消息前，ArcGIS 状态最终变为已连接；
4. 健康检查和上下文读取 R0 工具可用；
5. DPI 为 144（150%）且约 `853 × 533` CSS 视口时，输入区完整可见；
6. 上下文按钮可打开抽屉，关闭按钮和遮罩可关闭抽屉；
7. 全程不执行 GIS 写入、不保存项目。

## 9. 文档与可维护性

实现完成后同步更新：

- Phase 2 用户操作手册；
- 实机冒烟步骤和验收记录；
- SDD 进度与任务报告；
- 与事件兼容和安装布局有关的开发说明。

代码注释必须说明旧事件只是兼容别名，以及删除它所需的版本门槛，避免后续维护者误建第二套逻辑。

## 10. 完成条件

只有同时满足以下条件，本任务才算完成：

- 当前/旧版状态事件共享单一安全状态机；
- 新建对话主动触发状态列表且无需首次 LLM turn；
- 安装版自动解析同版本 MCP 路径；
- 150% 缩放实机布局通过；
- 自动化测试和相关构建全部通过；
- 事务性重装与只读实机冒烟通过；
- 文档更新完成，且没有凭据、用户路径、电子邮件或原始错误文本泄漏。

## 11. 回滚边界

本修复应保持为桌面兼容层的独立提交序列。若当前协议适配出现回归，可回退主动状态发现和归一化改动，而不回退已验证的 MCP Server、Add-In、安装器或 Phase 2 GIS 工具实现。CSS 修复和可执行文件路径解析也应保持可独立回退。
